Inside LiveJEPA

A Master's-thesis reconstruction of VL-JEPA's selective decoding: a video model that watches continuously, predicts meaning in embedding space, and spends its expensive language decoder only when something actually changes.

2.5× fewer decoder calls on redundant streams, at equal caption quality
5–26% better captions from averaging the predicted stream before decoding
25× caption quality from training the predictor in-domain
1.2% of the 2.5B-parameter system is trained

The architecture

Four stages. Only one of them is trained — everything else is a frozen, publicly released model. That 1.2% is the whole thesis.

frozen · watch V-JEPA 2 encoder 16 frames @ 2 fps → visual embedding tokens 326.0M params
→
trained · predict Predictor maps vision tokens into sentence-embedding space 29.9M params — the only trained part
→
frozen · decide SegmentTrigger fires when semantic shift 1−cos exceeds τ = 0.15 0 params
→
frozen · speak SONAR decoder turns the embedding into an English sentence 1,370.6M params

Total system ≈ 2.5B parameters; 1.2% trained. The 1.37B decoder sleeps through ~90% of video windows — that asymmetry is why selective decoding pays. (SONAR's 766M text encoder is used only at training time to build targets.)

The goal

VL-JEPA (arXiv:2512.10942) introduced selective decoding but released neither code nor weights. LiveJEPA rebuilds the mechanism end-to-end from released components and asks the scientific question honestly: when does decoding "only on change" beat decoding on a fixed clock? The answer — it depends on the temporal redundancy of the stream — is mapped with budget-matched, time-aligned CIDEr on public benchmarks, plus a live system the original paper never shipped.

What we found (the honest version)

Four results, in the order they happened — including the one that went the wrong way, and what it took to explain it.

result
Selective decoding wins where meaning is redundant. On COIN instructional videos it matches uniform decoding's quality with ~1.6× fewer decoder calls; on EgoExo4D keysteps ~2.5× (the paper's own headline form was 2.85×).
boundary
…but not where meaning changes constantly. On EgoExo4D atomic descriptions — a semantic event roughly every two seconds — uniform decoding wins at every budget, because there is nothing redundant to skip. On COIN's predicted stream, uniform also holds the 0.2 Hz band, which happens to match COIN's own step cadence. Mapping this boundary is a contribution, not a failure.
the headline
On a predicted stream, averaging — not placement — carries the gain. Re-running that same hyper-dense benchmark through the full pipeline, with a predictor trained in-domain, adaptive beats fixed-interval decoding of single windows at 7 of 8 budgets. But adaptive also averages each segment before decoding. Give fixed-interval decoding the same averaging — as VL-JEPA's own protocol does — and it matches adaptive: tied at 6 of 8 budgets, with one significant win each way. The predicted stream is noisy, and pooling it before decoding is what helps. That is an honest non-replication of the paper's adaptive-over-uniform claim, measured like for like.
result
It is not just cheaper — it is better. Measured by how closely each caption's embedding matches the reference, decoding every single window scores worse than pooled decoding at ~40× lower cost — because averaging a span cancels predictor noise that a single window carries, and fixed-interval spans do it as well as adaptive ones. One caveat we found ourselves: on this metric even a single caption per video scores high (0.695), so it rewards averaging in itself and cannot rank triggers. What limits caption quality is the predictor — in-domain training alone raised it 25×.
result
Data was the bottleneck, not the architecture. The scaling table above climbed +0.18 cos on the diverse val without touching a single hyperparameter.
negative
Two clean negatives, reported not buried. Training on Action100M — the corpus the original paper used — lost to COIN-trained models on Action100M's own validation set at matched scale, and adding it as extra data made the model slightly worse. The cause is target-vocabulary entropy: COIN has 747 recurring captions seen ~36× each, Action100M's preview has 6,096 seen ~once. Predicting open-vocabulary sentences from one example each is a far harder problem than mapping into a closed set.

Use it

Live demo
Upload any how-to/activity video (or use a sample) on the demo page — watch the semantic-shift meter cross τ exactly when a caption fires, and count the decoder calls it skipped. Download the result as .srt subtitles.
Where it fits
Always-on wearable assistants, kitchen/workshop copilots, sports commentary, CCTV summarisation — anywhere video runs for hours but meaning changes rarely, and every decoder call costs power, latency, or money. Runs fully local: zero cloud calls.
